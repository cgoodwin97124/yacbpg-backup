Yet Another Comic Book Page Generator

Design Document — version 2026.09.24.2

Written 2026-08-14. This document describes the generator as it is built today: what it does, how it works, how your data is stored, and how the pieces fit together.

1. What it is

Yet Another Comic Book Page Generator is a browser-based tool for assembling comic-book pages from AI-generated art. You describe a page as a sequence of panels — each with characters, a location, and a short action prompt — and the app renders each panel into 1–4 images using Perchance's text-to-image service. You can work across multiple pages, apply art styles and color presets, protect the images you like from being overwritten, and back everything up to a file.

Everything runs in the browser. There is no backend, no accounts, and no server-side storage — your project, your saved character/location libraries, and your settings live in your browser's local storage, and generated images live only for the current session (unless you download or export them).

2. Getting around the interface

The app has three main zones:

  • The menu bar (top, or a side column on wide screens) — File, Edit, Library, and Help, followed by ⚡ Generate All, ⏸ Pause, and ■ Stop. Only one group is open at a time.
  • The panel grid — your comic page, made of panel cards arranged in a grid.
  • The app header — page controls (Storyboard / Focus buttons, hide/show menu, menu side/top, full-screen menu, hide/show panels). The header is pinned to the top of the window, so it — and your project name — stays on screen while you scroll. When the menu is hidden you can also put ⚡ Generate All, ⏸ Pause, and ■ Stop up here (Edit → Preferences).

The menu groups

  • 📄 File — Save… / Save as… (writes your project to a file), Export Project (JSON or ZIP), Import Project, set the Images per Panel default (new and blank panels start at it; Apply to all sets every panel now), manage pages (add/delete), and set the Image Size.
  • 📝 Edit — global keywords (positive/negative), art style + color palette presets, the global seed, the NSFW mode toggle, Reset to Defaults, and ⚙ Preferences (the app-wide options — asking for a password when hiding the panels, whether menus open full screen, keeping the header visible in the other full-page views, keeping Generate All / Pause / Stop in the header when the menu is hidden, and the theme: Light / Dark / Match my device plus your accent colour).
  • 📚 Library — opens straight to your list of saved Characters and Locations (name + description) — there is no heading to click through — which appear at the top of the panel dropdowns. The ⬆ Import… button brings saved items in from a project file (.json or .zip): pick which Characters/Locations (and Actions, if any) to import, edit them, and resolve any name clashes. The header's ⛶ Full Screen button shows this same Library — the very same live list, so anything you type is saved at once — in a full-screen overlay, which is much roomier on a phone or a small window; you leave it with ← Back to page, the ⤡ toggle, or Esc. The same overlay can show the whole menu (see below). The 📊 Analysis button opens a full-page matrix of your library items against a page's panels — a ✅ shows where an item is used, the per-panel description can be edited in the grid, and ＋ Add drops an unused item into a panel. Its header also edits the project's NSFW state, default art style, default image size, and seed, a ▶ Panel Action Prompt row across the top (or column down the left after swapping) lets you read and edit each panel's action prompt right in the grid, and each panel also shows compact 🎨 style / 📐 size / 🎲 seed buttons you can click to change that panel (changes on other pages are saved to that page).
  • ❓ Help — about, the shortcut guide, and the version history. The changelog itself is loaded live from the project's GitHub repository the first time you open the About / Version History section; if GitHub can't be reached, a bundled version stamp is shown instead with a View on GitHub ↗ link.

Pages

A project can have as many pages as you like. The page selector sits in the File menu and the floating ＋ Add Page button is pinned to the bottom-right corner of the screen (the same green style as ▧ Hide Panels and the page navigator) so a new page is always one click away; ＋ Add Page appends a new page and 🗑 Delete Page removes the current one (deleting the only page resets the whole project — you're asked first). Each page keeps its own panel setup, seed, Page Title, Page Summary (an optional note shown in the Storyboard view), and generated images.

Reordering pages. With more than one page, a ⇅ Renumber Page control appears under the page selector. Pick a position and the current page moves there while every page is renumbered around it — e.g. with pages 1–5, renumbering page 4 to 2 makes the old pages 2 and 3 become 3 and 4. Each page's panels, title, summary, seed, and images stay with it.

Moving a panel to another page. A panel's ⇅ Move picker also lists the other pages (pages already holding the maximum 24 panels are greyed out) plus ＋ New page…. Moving to an earlier page appends the panel at the end of that page; moving to a later page puts it at the beginning; ＋ New page… creates a page holding just that panel. The panel's settings and its generated images travel with it, and the view switches to its new page. If the panel was the only one on its page, you're asked to confirm deleting that now-empty page.

Panels

Each panel card contains:

  • Header row — a label (on a multi-page project it reads Page P, Panel N; the Storyboard still numbers plain panels), an optional panel title, the Images count (1–4), a per-panel Style override, a per-panel Seed box with ⇤ copy-from-previous and ✕ clear buttons, a 🔄 Generate button, and a ⇅ Move control to reorder panels or move them to another page.
  • Info summary — a one-line summary of the panel's characters, location, and action.
  • Image slots — up to 4 images per panel. Each slot has its own small button row (see Managing images).
  • Action row — Show/Hide Menus (opens/collapses the panel's accordion menus with one button), 🔍 Focus (single-panel view), and 🔄 Generate (render just this panel).
  • Accordion menus — 📖 Panel Library (characters, location, action), 📝 Prompt (view/edit the exact prompt), ⚙ Panel (collapse menus, duplicate, add/delete panel, clear images), 💾 Files (open/save/export this panel's images).

3. Building a panel

Open a panel's 📖 Panel Library accordion to fill it in.

👤 Characters (up to 3)

Each character line is collapsible. Folded up (the default) it shows the character's dropdown — your saved characters first, then the built-ins — with a small ▸ arrow on its left and the ⇤ / ✕ buttons on its right. Click the arrow (it becomes ▾) and the line opens to show two description boxes: Library description — the saved description of the character you picked, shown read-only, exactly as it reads in 📚 Library (edit it there and this updates straight away) — and This panel — extra description, a freeform box for a phrase that tweaks that character for this panel only, e.g. "wearing a torn jacket" or "sprinting". Both are sent to the generator — library description first, then your extra text — and each is sent once. A red ✕ clears the line back to No Character Selected.

📍 Location

Pick a location (again: your saved ones, then built-ins) and, if you like, open the line with its ▸ arrow to add a per-panel extra description that flavours it for this panel. As with characters, the chosen location's library description sits read-only above your own text and is included in the prompt. Choosing No Location Selected clears the extra description. A red ✕ clears the whole line.

Tip: a line remembers whether it is open while you work, but every reload starts folded. Because the library description is shown separately — and is always included in the prompt — you never need to copy it into the panel box; that box is purely for extra, panel-specific wording.

🎬 Action Prompt

One or two lines describing what happens in the panel ("jumping through the air kicking a door"). Pressing Enter (without Shift) generates the panel immediately. A red ✕ clears the prompt.

⇤ Copy from the previous panel

Every character slot, the Location, and the Action Prompt has a small ⇤ button. Clicking it copies that item — including any freeform description/modifier — from the nearest earlier panel that actually has one. So set Hero + "cyber-ninja suit" on panel 2, click panel 3's ⇤ character button, and panel 3 gets the same character and modifier; click it again on panel 4 and so on. Panels with nothing in that spot are skipped over, so the ⇤ keeps working through a run of blank panels — and it reaches across pages: if page 1 has panels 1–8 filled in and everything after that is blank, panel 1 of any later page still copies from page 1's panel 8. Each ⇤ shows the panel it will copy from in its tooltip ("Copy this character from Page 1, Panel 8"), and it is greyed out only when nothing before it anywhere in the project has that item — panel 1 of page 1, for instance. The copy overwrites whatever that item currently holds, slot by slot (a panel's second character copies from the nearest earlier panel that has a second character). There is no automatic copying between panels — each panel gets exactly what you click into it.

🕘 Generated Prompt — the panel's prompt history

Inside each panel's 📝 Prompt menu there is a second, collapsible section, 🕘 Generated Prompt. Every time a panel generates — its own 🔄 Generate, a single image's 🔄 Generate, or ⚡ Generate All — the app files the exact prompt text that was sent (positive and negative, including your preset style keywords, characters, location, action and any 📝 Prompt override that was in force) together with the exact seed each image used and the time it ran. The newest five generations are kept, newest first.

These entries are frozen snapshots: changing a panel's characters, location, action, the global keywords, the presets or the NSFW flag never alters them, and neither does editing the live prompt editor. They are the record of what actually produced your images — so if an image came out well after you have since changed the panel, you can still see (and copy) the exact words and seed that made it.

  • 📋 Copy puts that saved positive prompt on your clipboard.
  • 🔄 Generate re-renders the panel from that entry — its saved prompt text and its saved seed(s) are used instead of whatever the panel currently says, so you get the same recipe again. It leaves the history exactly as it is: nothing is added, moved or reordered. 🔒 protected images are still respected, and the panel's own Seed box is left untouched.
  • Each entry shows its seed(s) — seed 123456, or img 1: 123456 · img 2: 123457 when a generation rendered several images, since image 2 uses the panel seed + 1, and so on.
  • The history is saved with the project, so it survives reloads and travels in Export / Import and the project .zip. It is read-only in the 🧩 JSON editor (shown greyed), because the app itself never edits it. ⧉ Duplicate copies a panel's history along with the rest of its settings; 🗑 Clear wipes it, while 🗑 Clear Images leaves it alone.

Titles, styles, seeds

  • Panel title is display-only — it never appears in the generated prompt.
  • Style overrides the global art style for that panel only ([Default (Global)] follows the Edit-menu preset).
  • Seed (in the panel header) pins the panel's randomness; leave blank to fall back to the global seed. An empty box shows, in grey, the seed the panel will use (the global seed + panel number − 1, or "random" if no global seed is set). Next to it are two small buttons: ⇤ copies the preceding panel's seed (or clears this panel's seed if that one is blank/random) and ✕ clears this panel's seed. Panel 1 of the first page has no preceding panel, so its ⇤ is disabled; on later pages Panel 1's ⇤ copies the last panel of the previous page.

4. Generating images

Click ⚡ GENERATE ALL PANELS ON PAGE to render every panel on the current page (the status line shows progress), 🔄 Generate on a panel for just that panel, or 🔄 Generate on an individual image slot for a single variation.

  • Empty panels are skipped — a panel needs at least a character, a location, or some action/description text to render: selecting a name alone is enough, even with no descriptions at all (the generator then makes its best guess — a saved "Holstein cow" with no description still renders a Holstein cow). If a panel has only 🔒 protected images, those are kept and reported.
  • ⏸ Pause — during a ⚡ GENERATE ALL PANELS ON PAGE run, Pause stops the run immediately. The panel it was working on is left paused (its in-flight image is discarded) and nothing else starts. Pressing ⚡ GENERATE ALL PANELS ON PAGE again continues from that panel — already-generated panels are not redone. The status line shows which panel it will continue from.
  • ■ Stop — the global Stop button next to ⚡ becomes active whenever any generation is running (batch, single panel, or single image) and cancels it cleanly; in-progress images are marked Stopped, and the next ⚡ run starts over from the first panel. Generation also pauses automatically if the browser tab goes to the background — pressing ⚡ when you return continues where it left off.
  • Timeouts — each image may take up to about two minutes; a stall shows a "Generation failed or timed out" tile you can retry.

How a prompt is built

Each panel's prompt is assembled from, in order:

  1. Style keywords — the global style preset (or the panel's own Style override) plus its color palette,
  2. the selected characters (their stored descriptions) with their per-panel modifiers,
  3. the location description and its modifier,
  4. the action prompt.

They're joined into one comma-separated prompt and sent to the text-to-image service. The 📝 Prompt accordion shows the exact prompt for a panel, and lets you override it entirely (positive + negative text of your own). Typing anything in the panel's characters/location/action fields discards that override and returns to the automatic prompt. The same accordion holds 🕘 Generated Prompt, the panel's history of the last five prompts it was actually generated with (with their seeds) — see that section above.

Seeds

Seeds make a generation reproducible. Slot k of a panel uses panel seed + (k − 1) (the panel seed defaults to the global seed + panel index, or completely random if neither is set). When neither is set, the first time a panel generates it picks a random seed and fills it into the panel's Seed box, so re-generating that panel reproduces the same image until you change or clear the box.

Image size & guidance

Image size is set in 📄 File → Image Size (e.g. 512×512 up to 768×768). Guidance scale (how closely the model follows your prompt, 1–30) is set in Edit. When the chosen size isn't a native service size, the result is upscaled to match.

NSFW mode

The NSFW toggle (Edit) switches off the automatic SFW safety keywords ("fully clothed" / "nsfw, nudity, explicit"). The filter is purely prompt-level: nothing is uploaded or stored differently.

5. Managing images

Under each generated image you'll find a small row of buttons:

  • ↗ Open the image in a new tab.
  • ⬇ Save it to your device.
  • ✕ Clear just that image (it aborts an in-progress render of that slot too).
  • 🔓 / 🔒 Protect — a protected image is never overwritten by regeneration (Generate skips it; unprotect to allow regeneration again).
  • ⭐ Make it the panel's representative/cover image — the one shown first (with a ⭐ badge) and used in Storyboard view.

Each panel also has 🗑 Clear Images (remove all images, keep the text setup) and 🗑 Clear (images and all characters/location/action).

Hover/long-press preview — hovering (desktop) or long-pressing (mobile) a panel image shows a large preview overlay. Delay and on/off are set in Edit.

Generated images exist only in the current browser session's memory — refreshing the page clears them (your settings and prompts are kept). Save any image you want to keep, or export a ZIP backup (see §8).

6. Pages & multi-page projects

Pages are numbered and hold up to 24 panels each (select 1, 4, 6, 12, 24, or a custom count per page). The page selector and page name live in File.

Copy between panels — each character slot, the Location, and the Action Prompt has a small ⇤ button that copies that item — with its description — from the nearest earlier panel that has one, skipping blank panels and reaching across pages. Nothing copies across panels or pages automatically.

Duplicate / Add / Delete panel (⚙ Panel) insert or remove panels and renumber the rest, preserving each panel's data and protection. On a page that already holds all 24 panels, ⧉ Duplicate and ＋ Add Panel do not stop you: the page's last panel is pushed to the top of the next page — and if that page is full too, its last panel is pushed onward the same way, cascading through as many full pages as there are and creating a new page when there is nothing left to push into. The new panel takes the slot that was freed, so it still lands immediately after the panel you clicked, and everything about a panel (title, characters, descriptions, seed, protection, and its generated images) travels with it to its new page. You are asked to confirm first, and told how many panels will move; the page you are viewing stays put.

Selecting several panels — each panel's header row begins with a checkbox. Tick one to select that panel, or Shift-click a checkbox to select the whole range from the last one you ticked; selected panels get a blue outline and tint. While anything is selected, the buttons in the ⚙ Panel menu of any selected panel work on the whole selection at once — 🔄 Generate, ⚡ Generate All From Here, ⧉ Duplicate, ＋ Add Panel, ⇅ Move, 🗑 Clear Images, 🗑 Clear and 🗑 Delete — and their labels show the count (⧉ Duplicate 3 Panels). Duplicate puts a copy right after each selected panel; Add Panel adds one new empty panel per selected panel, all together after the last of them; Move opens a picker that shifts the whole block to a new position on the page, to the front or end of another page, or onto a brand-new page. A small bar at the bottom of the screen shows how many panels are selected and offers 📋 Copy / ✂ Cut / ✕ Clear (Esc clears too), and Edit → Panel Selection has Select all panels, 📋 Copy, ✂ Cut and ✕ Clear selection. Clicking a panel's body never changes the selection — only its checkbox (or Esc) does. The selection is a working aid only: it is never saved with the project and it clears when you switch pages (after a batch move the moved panels stay selected, so you can nudge them again). The destructive buttons ask before they act and offer an Only This Panel escape, so a mis-click can still be narrowed to the one panel you are looking at. 🔄 Generate renders only the selected panels; ⚡ Generate All From Here starts at the first selected panel and runs to the end of the page. On a project with more than one page, 🗑 Delete also offers Delete & Refill: after removing the selected panels it pulls panels up from the following page(s) so the page keeps its panel count — the page you are deleting from is refilled from the top of the next page, cascading onward as needed, and a page that is emptied by that pull is deleted too (after its own confirmation). Deleting every panel of a page deletes that page. While the clipboard holds something, every panel's header also shows a 📋 Paste chip that inserts the copied panels before that panel — contiguously, with their settings and their generated images — using the same full-page reflow as Duplicate (it asks first if the page is full, and the overflow continues onto the following page, creating one if needed). 📋 Copy puts the selected panels on the clipboard; ✂ Cut does the same and then removes them from the page. Paste consumes a Cut — the chips disappear afterwards — while a Copy stays on the clipboard so you can paste it again and again until you copy something else. Cutting every panel of a page offers to delete the page (or, on a single-page project, to empty it down to one blank panel). The clipboard is a working aid like the selection: it lives in this tab only, is never saved with the project, and survives switching pages (but not a reload).

7. How your data is stored

Everything is stored in your browser (localStorage, plus IndexedDB for the silent "Save…" file handle). Nothing is sent to a server except the image prompts themselves (the text-to-image service).

Key Holds
comicGen.panelState The whole project: project name, image size, guidance, keywords, NSFW flag, current page, and every page's panels (characters + modifiers, titles, location + modifier, actions, seeds, image counts, the images-per-panel default, per-panel styles, prompt overrides, protection).
comicGen.charLibrary / comicGen.locLibrary Your saved characters and locations.
comicGen.preset The active art style + palette.
comicGen.* (activeMenu / layoutMode / menuVisible / panelsVisible) UI preferences.

Session-only (lost on reload): generated images, prompt overrides, and which accordions are open.

IndexedDB stores the File System Access handle used by 💾 Save… so the app can silently save to the same file you chose before.

8. Backup, export & import

  • 💾 Save… / Save as… — write the project settings to a JSON file (silent save to a remembered file, or pick a new one).
  • ⬇ Export Project — JSON (all settings + libraries + preferences) or ZIP (the same settings plus every generated image for every page). ZIP is the complete backup.
  • ⬆ Import Project — restore from a JSON or ZIP export. Importing starts with a safety prompt (it will replace the current project). ZIP imports restore the images into the right panels. A project (page) seed or a panel seed of -1 in the imported file means "random" and is quietly cleared on import — several external prompt pipelines use -1 that way, and this app would otherwise take it literally.

9. Editing the whole project as JSON (Project JSON Editor)

Edit → 🧩 Open JSON Editor opens your entire project as one formatted JSON document in a full-page editor. It is the same data as ⬇ Export Project → JSON — every page and panel, your saved characters/locations, the global keywords and size/guidance settings, the preset and the UI flags — so a document you edit here could equally be saved and opened in your own text editor.

Only the fields you can edit elsewhere in the app are editable. Everything else — the version numbers, the current page, library ids, and the document's structure — is shown greyed out and locked: editing it is refused with a clear message, so even a Replace all can never corrupt the project. Dropdown-backed values (image size, panel count, character/location selection) are checked against the same choices the app offers.

  • Find / Replace works inside the editable values only (never in keys or locked fields), with Regex and Match case options. 🔍 Find next jumps to the next hit, ⇄ Replace changes the highlighted one and moves on, and ⇄ Replace all asks first and tells you how many matches it is about to change (Cancel leaves the document untouched).
  • ✔ Apply validates the whole document before anything changes. Invalid JSON is reported at the exact spot and every problem — a locked field, a bad value, a removed entry — is listed: use ‹ Prev / Next › to step through them, which selects the offending text.
  • 🔄 Reload throws your edits away and rebuilds the document from the live project (it asks first when the document has unsaved edits).
  • Undo: ↩ Undo last apply puts the project back exactly as it was before your last Apply, while Ctrl+Z / Ctrl+Y undo and redo up to the last 10 edits you typed in the editor. Ctrl+F finds, Ctrl+S applies, and Esc (or ← Back to page) closes — asking first if you have unsaved edits.
  • Line numbers run down the left; the Syntax highlighting checkbox can be switched off for very large documents (locked and error highlighting stays). 📋 Copy puts the whole document on the clipboard.

Generated images are not part of this document — they live only in the current session and travel only in the ZIP export. Your GitHub backup token is likewise never included.

10. Layout & theming

The interface adapts to the screen: the menu sits on top normally, or as a side column on wide landscape screens (▤ Menu: Side). The ☰ button in the header hides the menu and brings it back — it reads Hide Menu while the menu is showing and Show Menu while it's hidden. ▧ Hide/Show Panels hides the whole panel grid while generation keeps running invisibly. The floating controls at the bottom of the screen (▧ Hide Panels, the page navigator, and ＋ Add Page) never sit on top of your content — the page keeps an empty strip at the bottom you can scroll past, and with the menu on the side the menu column is sized so its ⚡ Generate bar and status line always end above them. ▦ Storyboard shows one representative image per panel as a page overview (with the page's title and summary, and — on a multi-page project — its own ◀ / numbered pages / ▶ navigator next to "← Back to page"); 🔍 Focus works on a single panel at a time. ⛶ Full Screen in the header blows the menu up to fill the screen — File, Edit, Library, and Help all get the room of a full page (the tabs stay on screen so you can switch), which is a lifesaver on a phone. In fact the menu opens full screen by default: pick a section and it fills the screen, with your project name and the header buttons pinned along the top. Turn that off under Edit → Preferences if you would rather the menu stay tucked into the page; either way the header's ⛶ Full Screen button is that same switch. The status line sits at the bottom of the menu, and a generation that's already running keeps going while you are in the menu. Close the full-screen menu with ← Back to page or Esc.

Theme. Under Edit → Preferences → Theme you can run the whole app in Light, Dark, or Match my device mode, and choose an accent colour — eight presets plus a custom colour box and a Reset for the default amber. The accent is the highlight used for borders, active buttons and labels everywhere, and in light mode a pale accent is automatically deepened enough to stay readable. Your theme is saved with the project, so 💾 Save / Export / Import carries it (and it's editable in the 🧩 JSON editor). The app now starts in Match my device mode, so it follows your device's light/dark setting until you pick something here.

11. How it's built (technical overview)

The generator is a Perchance generator made of two source files plus a small src/ folder:

  • main.pjs — a small Perchance-js file: the app title, the character/location lists, and the import of the text-to-image plugin (generateImage). Its top-level names become page globals.
  • index.html — the entire application: styling, the full HTML layout, and one big JavaScript module containing all the logic (UI building, generation pipeline, persistence, backup).
  • src/ — auxiliary files shipped with the generator (this user manual). The development documentation — dev-notes, the request queue, the AI worker's notes, the issue log and the changelog — lives in the project's public GitHub repository (github.com/cgoodwin97124/yacbpg-backup), not in the shipped page. It had to move out of src/ in 2026-08-14 and off index.html in 2026-09-23.6, because the platform's save flow wedges on those filenames. index.html keeps only a tiny version stamp; Help → About fetches the changelog from the repo at runtime.

The rendering pipeline (the heart of the app):

  1. You click a Generate control.
  2. The app builds the prompt for the panel (§4) and resolves the image size and seed.
  3. For each image slot it calls the text-to-image plugin (root.generateImage) with the prompt, negative prompt, resolution, guidance scale, and seed.
  4. The plugin streams back an image (data URL); the app upscales it if the target size differs, then displays it and enables the slot's buttons.
  5. Batch runs loop panel-by-panel, honoring protection, skipping empties, and checking for Stop/pause at each step. A single global ■ Stop aborts every in-flight image.

The app deliberately uses only browser-native APIs — no frameworks, no external code beyond the text-to-image plugin — which keeps it fast and dependable on mobile as well as desktop.

13. Notes & limitations

  • Images are session-only — reloading clears generated art (settings survive). Use ZIP export for a durable copy.
  • Local storage is per-browser — your project lives in the browser you used; a different browser or a cleared profile starts fresh (unless you import a backup).
  • Generation speed depends on the text-to-image service; each image can take up to ~2 minutes.
  • Guidance scale is whole numbers only (1–30).
  • The NSFW toggle only affects prompt text — it's not a content filter on the returned image.
